# Football Time Machine — Feedback Log

Repeatable intake log for beta and ongoing product feedback. Capture real reports here; do not invent entries.

In-app email delivery setup: [FEEDBACK_SETUP.md](./FEEDBACK_SETUP.md).

**Workflow**
1. Capture the raw note using the template below.
2. Classify into a category section.
3. Interpret the problem (separate from the user’s wording).
4. Set severity and frequency.
5. Suggest an action and open a GitHub issue when warranted.
6. Update **status** as work moves (`new` → `triaged` → `in progress` → `done` / `wontfix` / `duplicate`).

**Severity guide**
- `critical` — blocks watching/progress, spoiler leak, data loss, or widespread outage
- `high` — major friction on a primary journey; wrong history on a featured match
- `medium` — noticeable UX/content issue with a workaround
- `low` — polish, minor copy, edge device quirk
- `positive` — keep as signal; no fix required

**Status values:** `new` · `triaged` · `in progress` · `done` · `wontfix` · `duplicate`

## Entry template

Copy this block for each new report:

```md
### YYYY-MM-DD — short label

| Field | Value |
|---|---|
| **Date** | YYYY-MM-DD |
| **Source** | e.g. in-app report, email, Twitter/X, friend/family, internal dogfood |
| **User type** | e.g. new visitor, returning beta user, editor, internal |
| **Page or journey** | URL and/or tournament + experience (Story / Essentials / Team / Every Match) |
| **Raw feedback** | Verbatim or close paraphrase |
| **Interpreted problem** | Our restatement of the underlying issue |
| **Severity** | critical / high / medium / low / positive |
| **Frequency** | once / recurring / widespread (and count if known) |
| **Suggested action** | Fix, investigate, document, defer, etc. |
| **Status** | new / triaged / in progress / done / wontfix / duplicate |
| **Related GitHub issue** | #N or URL (if none: —) |
```
